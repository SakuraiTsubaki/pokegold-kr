# Repository Structure

The repository starts intentionally small. Directories are added when real Korean target material exists.

Expected long-term areas may include `asm/`, `data/`, `text/`, `assets/`, `tools/`, `tests/`, `manifests/`, and `docs/`.

These names describe responsibilities, not a mandate to reproduce an upstream or another generation's project tree. The verified Korean target architecture determines the detailed layout.

Avoid repository-wide structural version churn. Improve policy and documentation in place. Git history is the historical record; the live tree should represent the current structure only.
